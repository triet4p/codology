# Changelog

## [Unreleased]

### Added

- Added the `codology` Python package scaffold with an importable static `codology.declarations` layer and a documented single `handler(self, ctx, ...)` convention.
- Added project packaging with `pyproject.toml` and `uv.lock`, plus the pytest baseline, Pyright strict configuration, and Ruff configuration.
- Added lazy forward-reference resolution for declaration annotations, resolved at link time against a composed namespace so modules can reference each other's types without runtime import cycles.
- Added `README.md` with install, test, and type-check commands, and `docs/official/design/implementation-baseline.md` recording the Python version, layout, tooling, and handler convention decisions.
- Added immutable class-based structural declarations (`Module`, `ObjectType`, `Value`, `Link`, `ObjectRef`) with explicit identity and version, typed properties, typed link specs, and frozen exports.
- Added immutable behavioral declarations (`Action`, `Function`, `Effect`) with typed params, `reads`/`writes`/`calls`, `permission`, commit requirement, and effect payload metadata, enabling tier-1, cross-module, and approval/effect declarations without executing handlers.
- Added structured approval predicates that preserve each comparison operator (including `>` versus `>=`) and reject lambdas, method calls, and other unsupported expressions with clear errors.
- Added a `load()` phase that collects declarations per owning module into an immutable model, keeps each declared identity and version, and rejects duplicate identities or unknown declaration fields with module, identity, and field context.
- Added a `link()` phase that resolves forward annotations and typed references across composed modules, rejects unresolved, wrong-kind, unexported, mismatched `ObjectRef[T]`, and mismatched handler declarations with module/identity/field context, and returns an immutable linked model without calling handlers.
- Added an immutable `snapshot()` view over the linked graph with version-explicit `(identity, version)` lookup and no implicit `latest`, exposing dependency edges and structured approval expressions that preserve comparison operators such as `>` versus `>=`. No handler digest is published.
- Added manifest-pinned revision resolution: `pin_manifest()` records the root Action, every reachable child Action/Function and declared Effect, and every identified ObjectType/Value dependency with a SHA-256 digest of the source module the revision was loaded from (line endings normalized). `encode_manifest()`/`decode_manifest()` keep the manifest portable and reject unknown fields, bad digests, wrong kinds, and duplicate revisions; `manifest_digest()` identifies the pin by its canonical bytes. `resolve_manifest()` accepts one or more linked revision sets, selects only the set whose exact revisions, dependency closure, kinds, and artifact bytes match the pin, and otherwise raises `MissingArtifact`, `DigestMismatch`, `KindMismatch`, or `ClosureMismatch` before any handler runs. No publish pipeline or registry is introduced.
- Added a durable waiting state at the `invoke` gate: an Action with a structured `approval` runs its handler in a discarded preview, evaluates the declared predicate on the resolved input, and returns `AWAITING_APPROVAL` with a unique execution ID, the pinned manifest, the material intent and a required approval (role, scope, requester, deadline, self-approval). The waiting record occupies the scoped request ledger under one key, so replay returns the same execution across restarts and default-revision changes while no order, budget or outbox write and no held transaction remains. Below the threshold the existing atomic commit path is unchanged; approval decisions, resume and effect delivery are not part of this change.
- Added a runnable Procurement/Finance example under `examples/procurement_finance/` that composes the public Load, Link, and Snapshot API and demonstrates duplicate identity, missing export, unresolved reference, handler type/signature mismatch, and lambda approval failures without a backend.
- Added `bind_action()` deployment binding for `ATOMIC` actions: it checks provider capability, the transitive write set across `calls`, a single enlisted session, and delegation grants against the declared `calls`/`permission` contract. Missing capability, unbound child writes, split sessions, and ambient or broadened delegation mappings are rejected before any handler or business transaction runs.
- Added a file-backed SQLite transaction adapter with guarded conditional writes checked by `rowcount`, and an engine-owned `commit_guarded_writes()` boundary that rolls back before commit on any failure. Money is represented as exact integer minor units (`MinorMoney`) with one pinned currency and no FX.
- Added an authorized `query()` read boundary: it checks a live read grant before reading, accepts only verified pushdown predicates, applies tenant/scope policy in the SQLite adapter before pagination and count, issues opaque policy-bound cursors with stable ordering, and returns typed versioned refs from rows. Unsupported predicates and link traversal fail closed without returning rows.
- Added a synchronous `invoke()` gate that checks live invoke authority, re-resolves query-issued refs under the current read scope, runs one declared handler with a narrow `HandlerCtx`, revalidates versions, and commits all registered guarded writes in one bound transaction. `DENIED` and `StalePlan` create no execution record and change nothing; `ctx.require` yields a terminal `REJECTED`; declared cross-module calls require a checked requester delegation.
- Added tier-2 child action dispatch: `ctx.call` runs the declared child handler at the exact revision pinned by the linked graph under a narrowed requester context, sharing the parent's unit of work and one physical transaction. Undeclared calls, missing `budget.reserve`, wrong instance scope, raw refs, child `REJECTED`/`DENIED`, direct writes to another module's object, and split sessions all fail closed. A separate tier-2 runtime Procurement/Finance contract lives beside the static tier-3 example, which `invoke` refuses to run.
- Added a durable request/result ledger: `invoke` accepts a scoped `request_key` and an optional canonical `intent_fingerprint`, commits the result beside every guarded business write in one transaction, and returns an already-committed result on replay without running the handler again. Reusing a key with a different intent is denied as `KEY_MISUSE`; rollback and denied attempts leave no committed record. `reconcile` reads a stored result under a separate execution-record permission and returns `UNKNOWN` when no trustworthy record exists.
- Added a runnable consumer example at `examples/atomic_approval/`: it reads a pending purchase order through `query`, takes `VersionedRef[PurchaseOrder]` from `row.as_ref()`, and invokes the tier-2 approval action against a file-backed SQLite adapter. The order approval and the Finance budget reservation commit in one physical transaction, with replay, refusal, split-binding and rollback paths documented and reported by the entry point.
- Added end-to-end integration tests for the executable example: one commit with matching workflow state and ledger row, read and invoke denials that leave the database unchanged, split binding rejected before any write, rollback after a partial write, two orders contending for one budget with exactly one commit, and replay after a lost response.

- Added an approval decision gate: `engine.approve()` and `engine.reject()` bind each callback to the current approval's key and material-intent fingerprint, check live approver role/permission, tenant, scope, `self_approval`, expiry and revocation supplied by the host, and record accepted decisions with a separate audit of every attempt. Replay under the same key rechecks authority, changed payloads are `KEY_MISUSE`, denied attempts do not claim the key, a valid reject ends once in `REJECTED` without business writes, and a valid approve is an input to resume rather than a commit.

### Fixed

- Fixed `invoke()` leaving the request-key transaction open when it returned a stored replay result; the unit is now rolled back and closed, so a later writer is not blocked by a leaked `BEGIN IMMEDIATE`.
- Fixed runtime transaction failures escaping `invoke()` as raw exceptions: a provider that does not host the bound session, a write lock that cannot be acquired within the adapter timeout, and an unconfirmed commit now return `UNKNOWN` with no execution record. The engine does not claim a rollback it cannot prove; callers reconcile before retrying.
- Fixed the SQLite unit of work leaving its connection open after `commit()`/`rollback()`; `close()` now releases the connection deterministically and remains idempotent. `SQLiteProvider` also accepts a `timeout` in seconds for lock acquisition.
